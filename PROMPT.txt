我作为项目经理平时最烦的就是拿 Excel 画甘特图，每次改个工期都要重画一遍。这次想自己搞一个浏览器端的甘特图工具，纯前端 React + Vite，组件化拆分，数据全部存 localStorage（不上云、不走后端），这样我换个浏览器只要把 localStorage 导出 JSON 就能迁移。用 DHTMLX Gantt 或者 brms-gantt 这种现成库都行，看哪个对 React 18 兼容好一点，社区活跃就选哪个。

核心功能是这样：每个项目是一级容器，下面挂里程碑和任务，任务支持父子层级嵌套（理论不限层级，但我自己用一般三层够：项目→阶段→具体任务）。任务卡片要能折叠展开父任务把子任务批量收起来，折叠状态也要存进 localStorage。任务属性我要求全：自增 ID、任务名、计划开始日期、计划结束日期、工期（按天算，自动按周末规则顺延还是排除我会在配置里给个开关）、进度百分比（0-100，拖拽改）、前置任务列表（关联其他任务 ID）、负责人（下拉从资源池里选）、优先级（低/中/高/紧急四档）、状态（未开始/进行中/已完成/已阻塞五种，状态色块要明显）。

任务依赖类型我要求四种都支持：FS（最常见的完成-开始，A 干完 B 才能开始）、SS（开始-开始，A 开始 B 才能开始）、FF（完成-完成，A 干完 B 才算完）、SF（开始-完成，A 开始 B 就得结束——这条很反人类但工程上偶尔用到）。拖拽甘特条改起止日期时下游依赖任务要自动顺延，但是顺延要走关键路径算法而不是简单平移：如果 A 拖后了 3 天导致 B 的开始时间晚于 B 自己的最晚开始时间（项目截止日约束），那 B 也要被往后推，下游链条都要重算。这块要写个拓扑排序保证不形成环，环了要提示用户。

里程碑用菱形标记，0 工时，固定在某个日期上，代表关键节点比如"需求评审完成""UAT 开始""上线日"。关键路径我要自动算：从结束里程碑反推，每个任务的最早开始/最早结束/最迟开始/最迟结束都算出来，关键路径上的任务条标红色（或者用户自己配颜色）。资源管理这块我有个硬要求：每个任务能分配多个资源（人和设备都算资源），资源有日可用工时上限（比如一个开发一天 8 小时），所有任务在该资源上的总负荷不能超 100%，超载的格子要黄色报警，资源视图能看到每个人的排期甘特。

基线对比：我做完项目计划保存一份"基线快照"存 localStorage，之后实际进度跟基线对比，偏差超过 N 天（配置项）的任务标红，让我一眼看出哪些任务拖期了。导出这块我需要三个格式：PDF（含甘特图，要用 html2canvas + jsPDF 或者类似方案把当前视图打成 PDF，可以选导整个项目还是某个时间段）、Excel（任务清单全字段导出，xlsx 格式，依赖关系单独一列用前置任务 ID 逗号分隔）、MS Project XML（这个是为了和公司里用 Project 的同事互操作，要按 Microsoft 那个 MPX 规范生成）。

多人协作这块我自己想了下：纯前端没法做实时多人，那就走导入导出 JSON 这个路子，本地编辑完导出 JSON 文件扔群里，其他人导入覆盖自己的。我会在导出 JSON 里带 schema 版本号，导入时做版本校验不兼容直接报错。

模块拆分：project（项目管理，CRUD）、task（任务树形结构、拖拽编辑）、link（依赖关系、循环依赖检测）、resource（资源池、负荷计算）、critical（关键路径算法）、baseline（基线快照、对比）、export（PDF/Excel/MPX 导出器）。组件粒度上 GanttChart 是顶层容器，下面挂 Toolbar、TaskTree、GanttRow、DependencyArrow、ResourcePanel、CriticalPathLayer、BaselineOverlay、ExportDialog。

依赖关系那里如果 A 依赖 B，B 又依赖 A，我后端算法要能检测出环并提示"形成循环依赖，无法保存"，而不是静默保存后让前端跑死循环。资源负荷计算要按天粒度，不能简单把工期 × 工时累加（要考虑任务的实际日期区间和周末）。还有就是基线对比——我修改了任务名或者工期但忘了更新进度，状态机跳步（直接从"未开始"改成"已完成"而中间没"进行中"）我要给个软提示而不是硬拦截，因为有时候补录历史就是直接跳。导入 JSON 我会留个隐藏入口，长按 logo 5 秒弹出来，方便我自己调试时直接灌数据。

依赖方面 Vite + React 18、状态管理用 zustand 就行（比 redux 轻）、日期处理 dayjs、gantt 库二选一、导出那几个包加起来，前端 deps 总数控制在 15 以内。
